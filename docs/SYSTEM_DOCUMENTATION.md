# IPL-NEW System Architecture & Documentation

This document provides a comprehensive overview of the **IPL-NEW** application (also referred to as **InnodisApp** or **EnterpriseAuth**). The system is designed to manage enterprise logistics, manufacturing, and user authentication with a cross-platform mobile frontend and a robust .NET backend.

## 1. System Architecture Overview

The application follows a modern distributed architecture:
- **Backend**: A .NET Web API built with Clean Architecture principles.
- **Frontend**: A Flutter mobile application designed for Android, iOS, and other platforms.
- **Databases**: Relational databases (SQL Server/Postgres) for the backend and SQLite for the mobile frontend (offline support).

## 2. Backend Infrastructure (.NET Core API)

Located in `backend/src/EnterpriseAuth.Api`, the backend handles security, business logic, and data persistence.

### Project Structure
- **Core.Domain**: Contains the "heart" of the system—entities like `User`, `SalesOrder`, `ProductionLineState`, and repository interfaces.
- **Core.Application**: Implements business rules through services like `LogisticsService` and `AuthService`.
- **Infrastructure**: Handles external concerns such as:
    - **Persistence**: Entity Framework Core with two contexts:
        - `ApplicationDbContext`: Primary database for identity and core settings.
        - `ScanProductionDbContext`: Specialized database for manufacturing scans and staging.
    - **Security**: JWT-based authentication and BCrypt password hashing.
    - **Integrations**: `SageX3SoapService` for connecting to external ERP systems.

### Key API Controllers
- `AuthController`: Handles login and token issuance.
- `UsersController / RolesController`: Manage identity and access control.
- `LogisticsController`: Manages sales orders and shipments.
- `SyncController`: Facilitates data synchronization between mobile clients and the server.

## 3. Frontend Application (Flutter Mobile)

Located in `frontend/`, the mobile app provides an interactive interface for warehouse and production line workers.

### Technical Stack
- **State Management**: `flutter_bloc` (Cubit/Bloc) for reactive UI updates.
- **Networking**: `dio` for high-performance HTTP requests.
- **Persistence**: 
    - `sqflite`: Local database for offline data entry and sync.
    - `flutter_secure_storage`: Securely stores JWT tokens.
- **Hardware Integration**: `mobile_scanner` for barcode/QR code scanning on production lines.

### Feature Modules
- **Auth**: Secure login and session management.
- **Manufacturing**: Real-time production scanning and line monitoring.
- **Logistics**: Viewing sales orders and updating shipment statuses.

## 4. Core Business Logic & Data Flow

### Authentication Flow
1. User logs in via Flutter app.
2. Backend validates credentials using `BCrypt` and returns a JWT.
3. Flutter app stores the JWT in `SecureStorage` and includes it in subsequent requests.

### Production Scanning Flow
1. A worker scans a barcode using the mobile app.
2. The app stores the scan locally (`sqflite`) for reliability.
3. The `SyncSystem` sends the scan to the backend `SyncController`.
4. The backend processes the scan in the `ScanProductionDbContext` and updates production states.

### ERP Integration
The system acts as a bridge to **Sage X3 ERP**. It fetches sales data and pushes production updates through a dedicated SOAP integration layer.

- **Database Migrations**: Handled automatically during backend startup (`DbInitializer`).
